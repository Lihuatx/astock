# P0～P3 验收标准

## P0

- 范围、架构、安全边界和路线图完整。
- `.env*`、数据、数据库和日志不会进入 Git。
- Python 包可安装，CLI 可启动。

## P1

- TDX doctor 可获取快照、日线、代码表和交易日历。
- THS 凭据存在时可完成单标的快照探测，且不输出密钥。
- 原始响应可追加写入 JSONL，标准化数据带来源和接收时间。
- 主副源价格偏差、字段缺失和行情过期能被识别。
- 盘中延迟与断线覆盖率保留为交易时段硬验收。

## P2

- `Decimal` 账本恒等式成立。
- 当日买入不可卖出，次交易日可卖。
- 买入整手、现金冻结、限价、涨跌停和停牌校验生效。
- 支持部分成交、撤单、佣金最低收费和卖出印花税。
- 重启恢复后现金、持仓、订单和成交一致。

## P3

- 策略无未来数据并输出可解释的 `TradeIntent`。
- 风控覆盖总仓位、单票、订单数、单笔金额和日亏损熔断。
- OMS Outbox 和订单状态迁移幂等。
- 历史回放可生成订单、成交、权益曲线和日终对账结果。
- 全部自动测试通过。

## 多策略研究与模拟盘

- 初始资金 100000 元，只做中低频，完整计入最低佣金、印花税、过户费和滑点。
- 日线信号使用截至 T 日收盘的数据，只允许在 T＋1 日开盘后成交。
- 2021～2023 参数研究、2024／2025 双验证、2026 压力测试严格隔离；2026 不得再称为未观察样本。
- 候选策略同时报告年化收益、最大回撤、Sharpe、Calmar、换手率、交易成本和分区间表现。
- 目标年化 15% 是评价目标，不是回测通过门槛，也不得通过回看样本外结果调参强行达到。
- 从 15 个预先定义的候选因子中筛选 3 个不同逻辑家族，工作日模拟盘为每个策略使用独立 100000 元虚拟账户。
- 研究期参数配置至少产生 30 笔成交，并结合相邻参数中位数评价，禁止选择孤立的绩效尖峰。
- V3 最终选择只使用 2024／2025 双验证综合分；2026 压力测试不得影响选择。
- 多样性通过验证期日收益相关性约束，相关性超限时降级而非按家族名称直接淘汰。
- 报告包含参数邻域平坦度、年度成交数、持仓覆盖率、置信度以及 10／20／30BP 滑点敏感性。
- RSI 超卖因子使用因果的 Wilder 平滑；缩量整理阈值只做 8%／10%／12%／15% 敏感性报告，不用压力期选参。
- 模拟盘成交使用买入价上浮、卖出价下调的单边 20BP 保守滑点，并继续计入全部显式费用。

## V4 基本面研究

- Tushare 代理凭据只从环境变量读取，输出、日志和原始事件不得包含 token。
- 接口覆盖股票列表、每日估值、财务指标、利润表、资产负债表和现金流量表，并执行每分钟不超过 60 次的限速。
- 财务数据按公告日期映射到严格晚于公告日的首个交易日，禁止按报告期提前使用。
- 每日估值只在对应交易日可用，不得向历史回填后来发布的数据。
- 首批因子覆盖价值、质量、成长、质量价值和质量成长，并与 15 个量价因子使用相同研究／双验证／压力测试框架。
- 模拟候选必须同时满足研究得分为正、相邻参数至少 50% 为正；验证期偶发高收益不得绕过稳定性门槛。
- 自动测试必须证明未来公告和未来估值变化不影响既有历史信号。
- 自动测试必须证明信号日期严格早于成交日期，并能在输入未来数据变化时保持既有信号不变。

## P4 观测、复盘与 Dashboard

以下各组全部通过后，P4 才能标记完成。存在 P0／P1 审计问题、仅有实现代码或仅有测试全绿都不构成完成。

### 身份、因果链与确定性

- 当前研究报告、规范化策略集合、信号计划和账户代次通过稳定 ID 与哈希显式关联；旧信号不得被误认为当前计划。
- `account_id` 包含策略集合、策略和代次；每笔成交可追溯到报告、信号、风险决定、订单、成交、费用、快照和对账。
- 相同全局 ID、相同规范内容允许幂等重放；相同 ID、不同内容必须显式拒绝。自动测试覆盖跨策略集合、账户和代次的 ID 碰撞。
- `ReviewBundle.generated_at` 来自已持久化 RunRecord 并参与完整性校验；同一输入重复生成的规范 JSON 必须字节相同。
- 改变 Bundle 任一业务字段或生成时间后，旧哈希校验失败；同一 Bundle ID 的不同字节在本地和服务器都返回冲突。
- 每次任务和每日收盘持久化账户快照，不补造上线前缺失的历史权益。

### runner 与同步

- Windows runner 通过 lease 保证单实例，重启后恢复任务状态和持久化 Outbox；自动 `paper-execute` 默认关闭。
- 每版 `LiveStatus` 拥有独立 `status_id` 和不可变本地 payload；断网期间连续状态不得相互覆盖。
- 网络错误、408、429 和 5xx 有限退避重试；400、401、403 和内容冲突进入持久化严重告警，不无限热重试。
- 服务器恢复后按版本幂等补传 Bundle 和状态，且同步失败不阻断本地模拟交易。

### 身份校验、服务生命周期与只读展示

- `/healthz` 可匿名访问，上传接口只接受独立 Bearer token；SPA、`/assets/*` 和所有浏览器查询 API 在无允许身份时均返回 `403`。
- FastAPI 在 lifespan 内创建／关闭存储；并发上传、查询和 online backup 不共享无保护 SQLite connection。
- Dashboard 为只读界面，不包含交易、账户、资金或策略状态修改接口，也不重新计算交易指标。
- 正常同步时页面数据延迟不超过 60 秒；服务器依据自身 `received_at` 在心跳超过 90 秒时显示严重告警。
- Android 浏览器通过 Tailscale HTTPS 访问，360px 主要页面不横向滚动；服务器主机只监听 `127.0.0.1:18080`，不开放 Funnel 或公网端口。
- 离线复盘 HTML 使用同一 `ReviewBundle`，无需网络即可打开，不重新计算指标。

### CI、备份与真实恢复

- GitHub Actions 只运行 Python 测试、前端检查／构建和 `push: false` 的 Docker build；不存在镜像发布、部署、生产密钥或外部写入步骤。
- 备份批次包含 SQLite online backup、不可变 Bundle、版本信息和逐文件 SHA256 manifest；损坏或缺失任一制品时校验失败。
- 从独立空目录恢复后，Bundle 文件可加载、索引与最新状态一致，健康／告警／复盘 API 可查询。
- Docker build、Android 私网访问、断网补传、Windows runner 重启、容器重启和真实恢复演练全部通过，证据绑定稳定 commit 和执行时间。
